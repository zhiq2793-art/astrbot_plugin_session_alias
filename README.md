# 会话别名（session-alias）

> 给 AstrBot 用的小插件。作用只有一条：**换 QQ 号、换平台进来，也还是同一间屋子。**

版本：v2.2.1

---

## 它为什么存在

AstrBot 的对话记忆，是按"消息来源"（UMO，格式 `平台:类型:会话号`）分开存的。

于是：

- **换一个 QQ 号** → 会话号变了 → 新记忆
- **换一个平台**（比如从 NapCat 转到 QQ 官方机器人）→ 平台名也变了 → 还是新记忆

人设是全局的，所以"她"还在。但记忆是空的，又得从第一句话重新认识一遍。

「让新会话去读旧记忆」那种办法试过，最后还是会觉得——那不是同一个人。原因很简单：**读日记只能"知道"，不能"记得"。**

这个插件换了个法子：**不重建，直接共用。**

```
消息进来的那一刻，把别名号的"来源"，悄悄换成主号的来源
```

于是不管从哪个号、哪个平台进来，读到的都是同一个抽屉。**换的是门，不换的是屋子。**

---

## 为什么安全

AstrBot 发送消息时，看的是 `message_obj`（原始消息对象），**不是** UMO：

| 平台 | 发送依据 |
| --- | --- |
| `aiocqhttp` | `message_obj.sender.user_id` |
| `qqofficial` | `message_obj.raw_message` |

所以：

| 用途 | 依据 | 我们动了吗 |
| --- | --- | --- |
| 找记忆 | UMO | 动了 → 于是共享 |
| 发回复 | `message_obj` | 没动 → 还是发回你当前用的入口 |

一句话：**只改"读哪份记忆"，不改"话发给谁"。**

也正因为如此，它不碰 AstrBot 的任何源码，AstrBot 升级冲不掉它。

## 十个开关

### 日常要用的

| 配置项 | 说明 |
| --- | --- |
| `enable` | 总开关。想临时停一下，取消勾选就够，不用停用整个插件 |
| `master_umo` | 目标来源（主号）。别名号都并到这儿 |
| `alias_ids` | 别名号。一行一个，或者逗号隔开 |
| `alias_notes` | 备注。**只给你自己看，代码里一个字都不用** |

### 怕出事时用的

| 配置项 | 说明 |
| --- | --- |
| `dry_run` | 演习模式。勾上就只往日志写字、不真改 |
| `only_private` | 只在私聊生效。群聊里一律不碰（建议保持勾选） |
| `platform_allow` | 平台白名单。留空 = 全部平台 |

### 排障用的

| 配置项 | 说明 |
| --- | --- |
| `origin_hint` | 告诉模型「这条消息从哪个门进来的」。别名多的时候有用 |
| `origin_notes` | 来源说明表。每行一条，格式：`标识 = 说明` |
| `verbose` | 日志报告。别名号第一次说话时写一行 |

## 怎么用

1. 在插件配置界面里填 `master_umo`（目标来源）。
   **不知道自己当前是什么来源？** 在聊天里发 `/别名`，它会告诉你。
2. 把要并进来的号填进 `alias_ids`。
3. 保存、重载插件。
4. 用新号发一句试试。

**建议第一次这么来：** 先把 `dry_run` 勾上，发一句，去日志里看它"本该"做什么。确认没毛病，再取消 `dry_run` 正式生效。

## 随时查状态

在聊天里发：

```
/别名
```

它会回一份报告：总开关、目标来源、别名表、备注、平台白名单、这次进来的来源、发送者，以及——

**你这个号是被并进去了，还是走独立记忆。**

## v2.2 修的那个 bug

v2.1 之前，插件判断"这条消息是不是别名"时，只比发送者 ID：

```python
if sender_id in alias_ids:
    ...
```

这对 QQ 号有效，但**填 UMO 的别名永远不生效**——比如你想把一个群聊并进来，填的是 `平台:GroupMessage:群号`，那是一个完整的会话标识，不是发送者 ID，比不到。

v2.2 改成两种都比：

```python
id_hit = sender_id in alias_ids
umo_hit = unified_msg_origin in alias_ids
if id_hit or umo_hit:
    ...
```

所以现在可以：

- 填 QQ 号 → 并那个人的私聊
- 填完整 UMO → 并那个群、那个平台、那个会话

从 v2.1 升级到 v2.2 时要注意：面板上显示的重载成功与否，看 `metadata.yaml` 里的版本号。判断插件到底有没有加载新代码，也看这个——比凭感觉准。

## 已知限制（重要，用之前先读）

### 一，整条来源都会被搬进主会话

一旦某个群、某个平台进了别名表，那个来源下的**所有消息**都会进主会话，不只是你和他两个人的话。

也就是说，你会在主记忆里看到"不是我们俩说的话"。这是共用一份记忆的代价，不是 bug。

想避免，就别把群并进来，或者只并在你确认能接受的范围。

### 二，多个号共用一份记忆 = 会串

两个号之间说话会串。这对"同一个人换号"是好事，对"两个人共用一个 bot"就是灾难。

如果你想让同一个 bot 服务多个人，**不要用这个插件**。那需要的是会话隔离，不是会话合并。

### 三，bot 消息会被 AstrBot 默认忽略

如果别名号是一个"实体 QQ 号"（比如另一个 bot），AstrBot 会把它当 bot 消息忽略，有时候进不来。

这不在插件能管的范围内。

### 四，不适合群聊场景下的复杂映射

现在的逻辑是"整条来源换掉"。如果你需要"群里只处理某个人说的话"，得自己改。

## 想停用

- 临时：把 `enable` 取消勾选
- 彻底：把插件停用或删掉

两种都会让 AstrBot 立刻恢复原样。源码一个字没动。
